📈 Privilege Escalation — king to root

Investigate Cron Jobs

$ cat /etc/crontab
* * * * * king cd /home/king/ && bash run.sh
* * * * * root cd /home/king/ && bash root.sh
* * * * * root cd /root/company && bash run.sh
$ cat root.sh
python /root/company/media/*.py

A cron job runs root.sh as root every minute from /home/king/. The file is owned by root but the directory is owned by king — meaning we can delete and replace it.

🎯 Key Takeaways

  • Python 2 input() is dangerous — it evaluates user input as code. Always use raw_input() instead.
  • Directory permissions matter. If a directory is writable by your user, you can delete any file inside it — even if owned by root.
  • Always check cron jobs during privesc — scripts running as root from user-writable directories are a common vector.
